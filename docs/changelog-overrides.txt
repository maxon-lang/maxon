# Corrections to what the commit messages said.
#
# The changelog is generated from git history and EVERY commit appears, so that a change cannot be
# missed by nobody having remembered to mention it. Nothing here can ADD an entry — this file only
# corrects or drops one, which is the case a `Changelog:` trailer could never serve: a commit message
# that came out wrong is exactly what cannot be fixed by anything written at commit time.
#
# Records are separated by blank lines. Each line is `<field>: <value>`, split on the FIRST `: ` — so
# a subject may contain one, and they routinely do.
#
#   commit:   the exact subject line. The key, because a rebase preserves messages and shas it does
#             not, and a key that has gone stale is REFUSED rather than silently doing nothing.
#   text:     what the entry should say instead. The commit link is still appended.
#   drop:     why this entry does not belong in a changelog. A reason, never a bare flag — a dropped
#             entry with no stated reason is indistinguishable from a mistake six months later.
#
# An override naming no commit, or more than one, is an error. One naming a commit outside the
# release being cut is inert and correct: this file accumulates.
