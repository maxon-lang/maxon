# The Maxon error-code registry -- the SINGLE SOURCE OF TRUTH for the 4-digit
# error-code space, shared by all three compilers.
#
# THIS FILE IS AUTHORED. Four files are GENERATED FROM IT, and none may be edited:
#
#   maxon-sharp/Compiler/ErrorCode.g.cs                (the C# bootstrap's enum)
#   maxon-selfhosted/Compiler/ErrorCodeRegistry.maxon  (v1's enum, deprecated)
#   maxon-shv2/Compiler/ErrorCodeRegistry.maxon        (shv2's enum)
#   docs/error-codes.json                              (the artifact TOOLS read)
#
# Regenerate them with:  maxon error-codes generate
# Verify them with:      maxon error-codes check   <- run by every build that USES one
#
# A duplicate number FAILS THE BUILD, naming both claimants. That is the whole
# point: this file exists because the number space used to be written down three
# times, and two agents took E3099 on the same day, each having correctly
# grepped a different copy.
#
# THIS GRAMMAR HAS EXACTLY ONE PARSER: maxon-sharp/Compiler/ErrorCodeRegistry.cs.
# It briefly had two -- the MCP's `lookup_error_code` hand-parsed it as well -- and
# they disagreed on five inputs, one of which reported `emittedBy: {}` for a code the
# bootstrap declares. A format described in two places is the same disease as a number
# space written in three. Tools now read docs/error-codes.json, which THIS parser emits
# and stamps with a hash of these bytes; a tool that finds the hash stale REFUSES to
# answer rather than answering from a copy nobody checked.
#
# FORMAT  (a KEY LINE is any line starting with whitespace; an ENTRY runs from its
#          header to the next header, and a blank line does NOT end it)
#
#   E<nnnn> <CanonicalName>        an entry; the canonical name IS the meaning
#       csharp     <MemberName>    this compiler emits the code, spelled thus
#       selfhosted <memberName>
#       shv2       <memberName>
#       reserved   <why>           nobody emits it -- but the number is TAKEN
#       doc        <prose>         repeatable; the text `lookup_error_code` returns
#
#   Key and value are separated by a run of SPACES OR TABS, and so are the number and
#   the canonical name. Blank lines and `#` comments are ignored anywhere, including
#   between an entry's key lines. An unknown key is an ERROR, never a skipped line.
#
# RULES THE CHECKER ENFORCES
#   - a number appears at most once
#   - a canonical name appears at most once
#   - one compiler never spells two codes with the same member name, and never
#     declares the same key twice on one entry
#   - an entry is either `reserved` (no compiler claims it) or claimed by >= 1
#   - EVERY CLAIM IS LIVE: a claimed member must be mentioned by that compiler's own
#     source. A claim naming a member nobody emits is a lie the registry tells about
#     itself, and 22 rows were telling it. (The converse is structural: a code that is
#     emitted cannot be absent here, because the enum is generated -- `ErrorCode.Foo`
#     does not compile unless this file put Foo in it.)
#   - every entry has at least one `doc` line
#   - the four generated files match, byte for byte
#
# The STAGE is DERIVED from the leading digit -- it is never written down:
#   1xxx lexer   2xxx parser   3xxx semantic   4xxx IR   5xxx code emitter
#   6xxx PE writer                                       9xxx internal
#
# TO ADD A CODE: take the next free number in the right band, add an entry here, run
# `maxon error-codes generate`, and WRITE THE CODE THAT EMITS IT -- the liveness rule
# fails the build if you stop after generating. Do not hand-edit a generated file; the
# check will catch you, which is the idea.
#
# NEVER REFERENCE A CODE BY ITS NUMBER OUTSIDE THIS FILE. Use the generated member
# (`ErrorCode.SemanticUnneededCast`, and `.Format()` if you need the "E3010" spelling).
# A literal "E3010" in a source file is a fourth copy of the number space, and renumbering
# the code leaves it pointing at nothing while every gate stays green.

E2054 ParserShiftCountNegative
	csharp ParserShiftCountNegative
	shv2 shiftCountNegative
	doc A shift ('shl'/'shr') whose count the compiler FOLDED and found NEGATIVE --
	doc 'a shl -1', 'a shl -(1)', 'let SHIFT = -1' ... 'a shl SHIFT'. A negative count is

	doc FOLDER, not the token shape: 'let SHIFT = -1' is the same -1 as the literal, and a
	doc check that only looked for a bare literal token missed its own motivating example.

	doc A generic type argument resolves to 'float' -- bare ('Box with float') or through a ranged

	doc rather than monomorphizing, so a type parameter is one opaque 8-byte GENERAL-PURPOSE slot; a

	doc the backend, it panicked on the x64 emitter's cross-register-file assertion.
	doc A DELIBERATE DIVERGENCE FROM BOTH REFERENCES, which accept it because they MONOMORPHIZE (the
	doc instantiation gets a genuine f64 slot). It is a compiler limitation, not a language rule, and
	doc the message says so rather than naming a workaround -- there is none at this milestone.
	doc It is asked BEFORE E2061 so a bare 'float' gets this message and not the ranged-typealias
	doc advice, which would direct the reader into the very panic this refusal exists to close.

E2065 DirectiveMalformedCondition
	shv2 directiveMalformedCondition
	doc A '#if' condition the directive grammar has no production for. Two shapes reach it: the
	doc condition itself does not parse (a missing ')', an 'and' with no right-hand side, a bare
	doc 'true' where a predicate call belongs, a condition that runs off the end of the file), or the
	doc condition parses but TEXT FOLLOWS IT on the same line.
	doc Split out of E2064, which names a different fault: there the condition reads fine and the
	doc function it calls does not exist, and the fix is to correct a NAME. Here there is nothing to
	doc look up. One code answering both told a reader with an unbalanced paren that their predicate
	doc name was unknown.
	doc The trailing-text shape is a REFUSAL where the bootstrap is silent (measured: it discards the
	doc remainder of a '#if' line, so '#if os(Windows) n = 5' assigns nothing). Accepting it is a
	doc wrong-answer generator: the tokens after the condition are emitted into the program as code,
	doc so '#if os(Windows) os(Linux)' is a hard error on Windows and silence on Linux, where the
	doc region is dead and the junk is skipped along with it. A condition ends at its own newline.

E2067 ParserBuiltinArgNamed
	shv2 builtinArgNamed
	doc A call to a bare compiler BUILTIN labels one of its arguments -- 'min(3.0, b: 5.0)'.
	doc A builtin's arguments are ALL POSITIONAL, at every index, because a 'name:' label names a
	doc PARAMETER OF A DECLARATION and a builtin has no declaration to have parameters. Nothing
	doc downstream could check such a label either: a builtin emits no call op, so it never reaches
	doc the slotting that validates a label against a callee's parameter names.
	doc NOT E2052/E2053, and that is the whole reason this code exists rather than reusing one of
	doc them. Both of those state the ORDINARY call rule -- 'only the second and later arguments
	doc take name: labels' -- which is FALSE for a builtin at every position. Reusing E2052 here
	doc would answer a labelled second argument with a sentence saying second arguments may be
	doc labelled.
	doc It fires only for callees whose arguments this compiler decides are positional, and that
	doc decision is stated in exactly ONE place, 'Parser.argLabelRuleForCallee'. TWO disjoint families
	doc answer that way, for the same reason and by different tests: the MATH intrinsics
	doc ('calleeTakesPositionalArgsOnly'), each of which IS a machine instruction; and every

E3099 SemanticCapturingClosureEscapes
	csharp SemanticCapturingClosureEscapes
	shv2 capturingClosureEscapes
	doc A closure that CAPTURES, ESCAPING the frame its captures point into.
	doc THE RULE: a closure that captures may not escape its defining frame.
	doc A closure captures BY REFERENCE: LowerClosureCreate allocates an environment and
	doc fills it with the ADDRESSES of the enclosing frame's stack slots, so that reads
	doc through a capture see later mutations of the captured variable. The environment is
	doc therefore only meaningful while that frame is alive. Let the closure outlive the
	doc frame and every captured read dereferences a dead frame -- the classic upward-funarg
	doc problem. It compiles clean and dies at runtime, so it is refused where the mistake
	doc is still legible rather than left to fault inside emitted code the author never wrote.
	doc The routes refused are every store the parser can see WITHOUT interprocedural
	doc analysis:
	doc - RETURNING one out of the frame that built it (`makeAdder` -- the common idiom, and
	doc the reason this exists). Returning a closure an OUTER frame built is fine and is
	doc allowed: that environment points into a frame that is still alive.
	doc - storing one in a struct FIELD, a GLOBAL/static, a CONTAINER (array/map literal)
	doc element, a union's associated-value PAYLOAD, or through a PAYLOAD BINDING (which
	doc looks like a plain local but is an alias INTO the enum's heap box, so assigning
	doc through it writes back). Each is one 8-byte slot holding the code pointer alone,
	doc and each is heap memory outliving every frame, so the store drops the environment;
	doc the call then passes env=0 and the first captured read dereferences null.
	doc DELIBERATELY NOT REFUSED -- the interprocedural route: a capturing closure passed as a
	doc CALL ARGUMENT to a callee that then stores it (`Handler.create(function(n) gives n +
	doc bump)`), and symmetrically a capturing closure arriving as a call's RETURN value. At
	doc that store the value is a *parameter*, and whether it carries an environment is a fact
	doc about the CALLER -- deciding it needs a per-parameter escape summary propagated over
	doc the call graph, i.e. escape analysis proper. That is scoped OUT of the bootstrap and
	doc stays a runtime nil-deref. Passing a capturing closure DOWN to a callee that only
	doc CALLS it is perfectly safe and must keep working.
	doc A NON-capturing closure is unaffected and must keep working -- it lowers to a plain
	doc MaxonFunctionRefOp, has no environment to lose, and passes every check above BY
	doc CONSTRUCTION rather than by an exception carved for it. It is what a table of handlers
	doc or passes keyed by a struct field is built from.
	doc What would MAKE the refused routes work is escape analysis plus by-value (or boxed)
	doc capture, so a closure's environment outlives the frame that built it. That is a real
	doc language mechanism and it is DELIBERATELY DEFERRED here: adopting it would change the
	doc by-reference capture semantics the closure specs currently pin. shv2 schedules it at
	doc P1.5, where it co-lands with `async` -- a green-thread capture IS an escape.

	doc the live bytes and abandons the rest. A staged element is therefore owned by NOBODY until a
	doc `setLength` publishes it, and is leaked outright if one never comes.
	doc Refused rather than fixed, and the choice is deliberate. Making ownership follow the staged
	doc slot would put a destructor gate on every managed `push` -- a hot path -- and would make the
	doc `[length, capacity)`-reads-ZERO invariant conditional, which five separate array operations
	doc currently rely on. Refusing costs none of that, and costs no capability: `[0, length)` is
	doc exactly what the ARRAY surface's own `set(index, value:)` covers, which is length-bounded,
	doc owns what it stores, and is unaffected. So the message names it.
	doc Refused at the call site, naming the element type, and only where that type is KNOWN. It
	doc needs no carve-out for an unbound type parameter: `.managed` is unreachable through a shared
	doc generic body at all (a field access through it is refused one step earlier), so every site
	doc this rule can see has a concrete element.

	doc A bare `spawn f()` over a free function is refused here too, and deliberately: there is no
	doc unstructured green thread in this language. The unit of concurrency is a service, whose message
	doc surface the compiler can check.
	doc The cure is to name a static factory of the type you mean to start.

E3135 SemanticServiceValueNotTransferable
	shv2 semanticServiceValueNotTransferable
	doc A message of a service declares a parameter whose value cannot cross to another green thread.
	doc A send MOVES its arguments -- the receiving thread becomes their one owner -- and that is what keeps
	doc reference counting PLAIN rather than atomic: the language guarantees one green thread per box, so a
	doc send that left two threads holding one box would corrupt the heap rather than merely be slow.
	doc Four shapes fail it. A `Promise` is a green-thread handle its awaiter owns. A function value reaches
	doc a captured environment block, which is a box with a second referent by construction. A value held at
	doc an interface type is a fat pointer whose witness half is read-only data and whose value half is
	doc released through `__drop_existential`, a pair the request union's payload cascade cannot carry. An
	doc opaque type parameter has no layout at the send, so the sender cannot know what it is handing over.
	doc The diagnostic fires at the `spawn` that made the type a service, which may be in a different file
	doc from the method it names: whether a type is a service is a whole-program property, and the site that
	doc decided it is the one worth naming.
	doc The cure is to send a `.clone()`, to send the scalar the value is derived from, or to drop the
	doc parameter from the message and reach the value another way.

E3136 SemanticServiceNotAMessage
	shv2 semanticServiceNotAMessage
	doc A member was called on a service HANDLE that is not one of the service's messages.
	doc A handle's surface is exactly its service type's `export` INSTANCE methods, one variant of the
	doc synthesized request union each. That is the isolation boundary, and it is also what makes self-send
	doc deadlock unspellable rather than diagnosed: a private helper is not on the handle, so a call to one from
	doc inside a message body can only ever be a DIRECT call on the service's own state.
	doc Two shapes reach it, and the message tells them apart because the cures differ. The member may be
	doc DECLARED on the service type and merely not exported -- a private helper, or a `static`, which has no
	doc receiver and so can never be a message -- in which case `export` makes it one, or the value can be
	doc reached through a plain (unspawned) value of the type. Or nothing declares it at all, which is an
	doc ordinary misspelling.
	doc It is neither E3018 (a missing FIELD) nor E3004 (an undefined FUNCTION): the member usually exists, on
	doc the type, and saying otherwise would read as a typo.

E3138 SemanticServiceArgumentNotUnique
	shv2 semanticServiceArgumentNotUnique
	doc A message argument cannot be proven to have exactly one owner, so it may not be sent.
	doc A send MOVES: the service becomes the argument's one owner, and the sending frame gives up the
	doc reference it held. That is what keeps reference counting PLAIN rather than atomic -- the language
	doc guarantees one green thread per box -- so an argument this frame still shares with something else
	doc would put one box in two green threads' hands, which corrupts the heap rather than merely being slow.
	doc Three shapes fail it, and E3135 is the neighbouring rule about the argument's TYPE rather than its
	doc ownership. The first is an OWNED value this frame has already taken a second reference to -- a value a
	doc closure captured, one pushed into a container, one handed to another consuming call. The second is a
	doc BORROWED aggregate this frame does not own at all -- a struct read out of a field, an element, or a
	doc parameter -- for which there is no owning copy the send could take instead. (A borrowed `String` is
	doc not in this class: a byte record has a cheap owning copy, so the send promotes it and the source stays
	doc readable.)
	doc The cure for those two is `.clone()`, which is explicit precisely because it is O(n) and the language
	doc makes costs visible; or restructuring so the value is freshly built at the send.
	doc The THIRD is about what the record HOLDS rather than about the record: SOLENESS IS NOT TRANSITIVE.
	doc A box this frame owns alone may point at a record a second owner holds too, because every co-owning
	doc store (a struct-field or union-payload move-in of a borrow, a consuming call, a container push) takes
	doc a reference where a move would give one up -- and a send moves the record WHOLE, leaving that second
	doc owner behind on this green thread with a plain refcount racing the service's. It is asked of the
	doc record's TYPE, because the retain can happen inside a callee the send site cannot see. What may cross
	doc is a scalar, a `String` (whose slots hold bytes, never a second reference), a service HANDLE, and a
	doc record whose every slot is one of those; a container never crosses, whatever its element type is.
	doc This arm is deliberately conservative and refuses sound programs too -- proving the safe half needs a
	doc record's whole graph tracked through the co-owning stores, which is a whole-program fact shv2 does not
	doc compute. The cure is to send the scalars the record is built from.

E6003 BinaryOutputNotWritten

	doc build removed that path before compiling, so its ABSENCE afterwards means the writer did not

E3140 SemanticServiceReplyNotCarriable
	shv2 semanticServiceReplyNotCarriable
	doc A `spawn` makes a type a SERVICE, and one of its reply-bearing messages declares a reply the compiler
	doc cannot carry back to a sender.
	doc A reply resolves through a CELL -- a green thread that never runs -- and a cell carries exactly TWO
	doc words: the value, and one error word.
	doc The VALUE word is one machine word the awaiter reads back verbatim, so it holds what a green thread's
	doc result register holds: an integer, a `bool`, a `String`, a struct, a service handle. A `float` comes
	doc back in a floating-point register the cell has no slot for; a value held at an interface type or an
	doc opaque type parameter is a pair whose second half is released through a companion the cell does not
	doc carry.
	doc The ERROR word holds the FUSED ORDINAL of a two-member dispatch line -- `ServiceError` (what the
	doc transport can fail with, whatever the message declares) beneath the message's own error type -- which
	doc is what lets `match e` tell a stopped service apart from a handler that threw, using the same
	doc tag-interval dispatch every other `match` uses. A payload-free `enum` fits that line exactly, because
	doc its flag IS an ordinal. A payload-carrying `union`'s flag is a heap BOX POINTER instead, and a
	doc float-backed enum's tags are IEEE-754 bit patterns that can span more of the i64 range than the line
	doc has left above `ServiceError`'s own slice.
	doc It fires at the `spawn` rather than at a send, as every service diagnostic does, and for a reason of
	doc its own beyond the usual one: the dispatch loop the compiler synthesizes completes a reply for every
	doc reply-bearing message of the type, so a message the cell cannot carry would put a wrong-width store
	doc into a body the service really runs, whether or not the program ever sends that message.
	doc The cure is to return a value that fits the word and throw a payload-free `enum`, or to drop the
	doc `returns` and `throws` clauses -- which makes the message fire-and-forget, with no reply to carry.

E3137 SemanticServiceReplyAliasesState
	shv2 semanticServiceReplyAliasesState
	doc An `export` method of a SERVICE returns a value the service's own state can still reach, so the caller
	doc would end up holding a second reference to it -- on another green thread.
	doc A service is a green thread with a mailbox, and the language guarantees one green thread per box: that
	doc is what makes a reference-count step a plain load/add/store rather than an atomic one. A reply that
	doc aliased service state would put one box in two green threads' hands, which corrupts the heap rather
	doc than merely being slow -- the same rule a message ARGUMENT obeys by MOVING, read from the other end.
	doc What is refused is a return this frame does not solely own: a field read yields a BORROW, and so does
	doc `self`. An ordinary function promotes such a return by taking a reference (`__mm_retain`), and that
	doc promotion is exactly what would make the second namer. What passes is a value this frame MINTED -- a
	doc fresh record, an interpolation, a `.clone()` -- or a call result the compiler can prove fresh; and a
	doc scalar, which owns nothing at all.
	doc The cure is `.clone()`, and here the clone is RIGHT rather than a workaround: the caller genuinely
	doc asked for a copy, and a copy is the only thing that can cross.
	doc The diagnostic names the RETURN and carries the `spawn` that made the type a service as a note --
	doc whether a type is a service is a whole-program property, and the `spawn` deciding it may be in a
	doc different file from the method the rule fires on.

E3139 SemanticServiceCallCycle
	shv2 semanticServiceCallCycle
	doc Two or more services can await replies from each other, so a message of each could be blocked waiting
	doc on the other. Mutual reentrancy is made UNREPRESENTABLE rather than diagnosed at run time.
	doc The compiler builds a directed graph over service TYPES and refuses any cycle in it. An edge `A -> B`
	doc exists when a message of `A` AWAITS a reply from a `B.handle` -- transitively through ordinary
	doc functions, so a message that calls a helper that awaits still contributes the edge.
	doc ONLY BLOCKING EDGES COUNT. A fire-and-forget send is not an edge, because a non-blocking send cannot
	doc participate in a wait cycle -- which is what keeps peer-to-peer messaging legal, and is the whole of
	doc why the rule is not crippling.
	doc Why acyclicity is sufficient rather than merely suggestive: an acyclic graph has a topological order,
	doc the service lowest in it awaits nobody and so always makes progress, and by induction every blocked
	doc caller eventually resumes. There is no configuration in which everyone is waiting.
	doc A SELF-EDGE is a cycle too, and it is the one users hit most: a `Worker` whose message awaits a reply
	doc from another `Worker` is refused even though two distinct instances would not actually deadlock. Edges
	doc are by TYPE, which is what makes them statically knowable at all, so the analysis cannot tell the
	doc instances apart and must be conservative -- the guarantee is deadlock freedom.
	doc The cure is to break the cycle: make one of the calls fire-and-forget (drop the `returns` and `throws`
	doc clauses, or send it as a statement and do not await it) and have the peer reply with a separate
	doc message, or split the role into two types.
