# Spec-port log

The dated trend of the `/spec-port` loop — one row per tick, read downwards. It records **what the loop
did**, the way `docs/optimization-log.md` records what the compiler's cost did. It is a TREND, not a
backlog: it never holds work. Work the loop uncovers but that is not this spec's — a defect in another
mechanism, a rung nobody has reached — goes to `maxon-shv2/PLAN.md`. **A case in the spec being ported is
never such work; that is implemented, not filed.**

⛔ **NOTHING IS LOAD-BEARING HERE, AND THAT IS A CHANGE.** This log used to retire a spec from the loop:
a `DEFERRED` row meant the selector skipped it forever. **Deferring is gone** (user ruling 2026-08-02,
`.claude/skills/spec-port/SKILL.md` §4 — you implement until every case passes, however large), the
selector no longer reads this file at all, and `PORTED` is the only outcome a row can carry. A spec
leaves the loop by being ported and by nothing else.

The order the loop walks is `maxon-selfhosted/Testing/SpecTestRunner.maxon`'s `whitelist` — ~265 names
ordered easiest-first by the v1 loop that earned the ordering.

`cases` is *cases passing / `<!-- test:` markers in the file*, and **the two are always equal** — a tick
does not end until they are. Rows dated before 2026-08-02 may show a shortfall; that is the old process,
and the difference is cases it disabled rather than implemented. Those are debt, not precedent.
