## Overview

This spec defines AES-GCM, the authenticated encryption with associated data (AEAD) of NIST SP 800-38D, restricted to a 96-bit (12-byte) nonce and a 128-bit (16-byte) tag:

- **seal** -- encrypts a plaintext and authenticates it together with associated data (AAD), returning the ciphertext followed by the tag.
- **open** -- verifies the tag and, only if it is valid, returns the plaintext.

The `seal`/`open` contract is common to AEADs (RFC 5116): `seal(key, nonce, plaintext, aad)` returns RFC 5116's ciphertext (the encrypted plaintext with the tag appended), and `open` returns the plaintext or a single authentication failure. The `chacha20-poly1305` spec has the same shape and the same `AeadError` type. AES-128-GCM, AES-192-GCM and AES-256-GCM are selected by the key length. The block cipher is the `aes` spec's `encrypt_block`.

**Out of scope:** nonces of any length other than 12 bytes (SP 800-38D allows other lengths; they are an `InvalidNonceLength` error here); tags shorter than 16 bytes; GMAC used alone; nonce generation (SP 800-38D section 8.2); streaming or in-place interfaces; detached tags; AES-GCM-SIV.

## Types

### AeadError

```pseudocode
type AeadError =
  | InvalidKeyLength       // the key is not 16, 24 or 32 bytes
  | InvalidNonceLength     // the nonce is not exactly 12 bytes
  | PlaintextTooLong       // seal only: the plaintext is longer than 2^36 - 32 bytes
  | AuthenticationFailed   // open only: the sealed input is shorter than 16 bytes, or the tag does not verify
```

`AuthenticationFailed` carries no detail: a modified ciphertext, tag, AAD, nonce or key, a truncated input and an input too short to hold a tag all give the same error.

### Lengths

| Item | Length |
|---|---|
| Key | 16, 24 or 32 bytes (AES-128, AES-192, AES-256) |
| Nonce | exactly 12 bytes |
| Tag | exactly 16 bytes |
| Plaintext | 0 to `2^36 - 32` bytes (`2^32 - 2` blocks) |
| AAD | 0 to `2^61 - 1` bytes |
| Sealed output | `length(plaintext) + 16` bytes |

## Functions

### seal

```pseudocode
seal(key: Bytes, nonce: Bytes, plaintext: Bytes, aad: Bytes) -> Bytes | AeadError
```

**Parameters:**

| Name | Type | Required | Description |
|---|---|---|---|
| `key` | Bytes | yes | 16, 24 or 32 bytes |
| `nonce` | Bytes | yes | Exactly 12 bytes; MUST be unique per key |
| `plaintext` | Bytes | yes | Any length from 0 to `2^36 - 32` bytes |
| `aad` | Bytes | yes | Associated data, authenticated but not encrypted; MAY be empty |

**Returns:** `ciphertext || tag`, `length(plaintext) + 16` bytes, or `InvalidKeyLength`, or `InvalidNonceLength`, or `PlaintextTooLong`.

**Algorithm:**

1. If `length(key)` is not 16, 24 or 32, return `InvalidKeyLength`.
2. If `length(nonce) != 12`, return `InvalidNonceLength`.
3. If `length(plaintext) > 2^36 - 32`, return `PlaintextTooLong`.
4. `H = encrypt_block(key, 0^128)` (sixteen zero bytes).
5. `J0 = nonce || 00 00 00 01`.
6. `ciphertext = GCTR(key, inc32(J0), plaintext)`.
7. `S = GHASH(H, aad || zeros(-length(aad) mod 16) || ciphertext || zeros(-length(ciphertext) mod 16) || be64(8 * length(aad)) || be64(8 * length(ciphertext)))`.
8. `tag = encrypt_block(key, J0) XOR S`.
9. Return `ciphertext || tag`.

### open

```pseudocode
open(key: Bytes, nonce: Bytes, sealed: Bytes, aad: Bytes) -> Bytes | AeadError
```

**Parameters:**

| Name | Type | Required | Description |
|---|---|---|---|
| `key` | Bytes | yes | 16, 24 or 32 bytes |
| `nonce` | Bytes | yes | Exactly 12 bytes, the one given to `seal` |
| `sealed` | Bytes | yes | `ciphertext || tag` as returned by `seal` |
| `aad` | Bytes | yes | The associated data given to `seal` |

**Returns:** The plaintext, `length(sealed) - 16` bytes, or `InvalidKeyLength`, or `InvalidNonceLength`, or `AuthenticationFailed`.

**Algorithm:**

1. If `length(key)` is not 16, 24 or 32, return `InvalidKeyLength`.
2. If `length(nonce) != 12`, return `InvalidNonceLength`.
3. If `length(sealed) < 16`, return `AuthenticationFailed`.
4. Split `sealed` into `ciphertext` (all but the last 16 bytes) and `tag` (the last 16 bytes).
5. Compute `expected_tag` from `key`, `nonce`, `ciphertext` and `aad` exactly as `seal` steps 4, 5, 7 and 8 do.
6. If `expected_tag != tag`, compared in constant time, return `AuthenticationFailed`.
7. Return `GCTR(key, inc32(J0), ciphertext)`.

### GCTR and inc32

```pseudocode
inc32(X)  = X[0..11] || be32((uint32(X[12..15]) + 1) mod 2^32)
GCTR(key, ICB, X):
  CB = ICB
  for each 16-byte chunk X_i of X (the last chunk MAY be shorter):
    Y_i = X_i XOR first length(X_i) bytes of encrypt_block(key, CB)
    CB = inc32(CB)
  return Y_1 || Y_2 || ...
```

With a 12-byte nonce the counter starts at 2 for the first plaintext block and cannot wrap within the maximum plaintext length.

### GHASH

```pseudocode
GHASH(H, X):           // X is a multiple of 16 bytes
  Y = 0^128
  for each 16-byte block X_i of X:
    Y = (Y XOR X_i) * H        // multiplication in GF(2^128)
  return Y
```

GF(2^128) uses the polynomial `x^128 + x^7 + x^2 + x + 1` with GCM's reflected bit order: bit 0 of a block is the most significant bit of byte 0, and it is the coefficient of `x^0`. Bitwise multiplication (SP 800-38D algorithm 1), with `R = e1 || 0^120`:

```pseudocode
mul(X, Y):
  Z = 0^128; V = Y
  for i in 0 .. 127:
    if bit i of X == 1: Z = Z XOR V        // constant time: Z = Z XOR (V AND mask(bit i of X))
    if bit 127 of V == 0: V = V >> 1
    else:                 V = (V >> 1) XOR R   // constant time: V = (V >> 1) XOR (R AND mask(bit 127 of V))
  return Z
```

`>>` shifts the 128-bit block towards higher bit indexes, that is towards the last byte. Both conditionals above MUST be written as masks, not branches (see Behavioral Contracts).

## Behavioral Contracts

### seal()

**MUST:**

1. MUST return the SP 800-38D ciphertext and full 16-byte tag, concatenated, for all three key sizes.
2. MUST check the key length, then the nonce length, then the plaintext length, before computing anything.
3. MUST accept an empty plaintext (the output is the 16-byte tag alone) and empty AAD.
4. MUST return `PlaintextTooLong` for a plaintext longer than `2^36 - 32` bytes; it MUST NOT wrap the 32-bit block counter.

### open()

**MUST:**

1. MUST check the key length, then the nonce length, then `length(sealed) >= 16`, then the tag, in that order.
2. MUST return `AuthenticationFailed` for every input whose tag does not verify: any change to the ciphertext, the tag, the AAD, the nonce or the key, and any truncation or extension of `sealed`.
3. MUST compare the computed and received tags in constant time: the time taken MUST NOT depend on how many leading bytes match (the `hmac` spec's `constant_time_equal`).
4. MUST NOT release any plaintext when authentication fails: not a partial result, not a buffer the caller can read, not a decryption done before the tag check whose output escapes. Decrypting into a private buffer before the check is permitted only if that buffer is overwritten and never returned on failure.
5. MUST return exactly the plaintext `seal` encrypted, for every valid input.

### Common

**MUST:**

1. **Constant time.** The block cipher MUST satisfy the `aes` spec's constant-time contract. GHASH MUST also run in constant time: no table lookup indexed by bits of `H`, of the GHASH state or of the data, and no branch on them. The 4-bit and 8-bit table methods of the GCM paper (Shoup's tables) are therefore forbidden in software; use a carry-less multiply instruction (PCLMULQDQ on x86-64, PMULL on ARMv8) or a constant-time software multiplication.
2. `open(k, n, seal(k, n, p, a), a) == p` for every valid `k`, `n`, `p` and `a`.

**SHOULD:**

1. SHOULD overwrite `H`, the round keys and the expected tag before returning.

The caller MUST NOT seal two different messages with the same key and nonce: a repeated nonce reveals the XOR of the plaintexts and lets an attacker recover `H` and forge tags. This is a requirement on the caller, not a checkable property of `seal`.

## Test Vectors

Binary arguments are lowercase hex in `key_hex`, `nonce_hex`, `plaintext_hex`, `sealed_hex` and `aad_hex`. A `seal` result is `ciphertext || tag`; an `open` result is the plaintext. Tags `aes-128`, `aes-192` and `aes-256` give the key size.

### Sources

- `mcgrew-viega` vectors are the test cases of the GCM specification by McGrew and Viega (appendix B) that use a 96-bit IV: cases 1-4 (AES-128), 7-10 (AES-192) and 13-16 (AES-256), each as a `seal` and an `open` vector. Cases 5, 6, 11, 12, 17 and 18 use 64-bit or 480-bit IVs and are out of scope.
- `nist-cavp` vectors are from the NIST CAVP `gcmtestvectors.zip`. `gcm-encrypt-ext-iv` vectors are `COUNT = 0` of the `[IVlen = 96]`, `[Taglen = 128]` sections of `gcmEncryptExtIV128.rsp`, `gcmEncryptExtIV192.rsp` and `gcmEncryptExtIV256.rsp` with (`PTlen`, `AADlen`) in bits of (0, 0), (0, 128), (128, 0), (104, 160) and (408, 720), each as `seal` and `open`.
  `gcm-decrypt-fail` vectors are the first `FAIL` records of the (0, 0) and (128, 128) sections of `gcmDecrypt128.rsp`, `gcmDecrypt192.rsp` and `gcmDecrypt256.rsp`.
- `wycheproof-tc-N` vectors are from Project Wycheproof `testvectors_v1/aes_gcm_test.json` (test-case id `N`). Every `valid` entry with a 96-bit IV is a `seal` vector, and those with a plaintext of at most 16 bytes are also `open` vectors. Every `invalid` entry with a 96-bit IV (all are `ModifiedTag`) is an `open` vector expecting `AuthenticationFailed`.
  Entries with IVs of 0, 64, 128 and 1024 bits supply the `InvalidNonceLength` vectors tagged `wycheproof`.
- `constructed` vectors modify the `seal` output of McGrew-Viega test case 16 (AES-256, 60-byte plaintext, 20-byte AAD): a flipped ciphertext bit, a flipped tag bit, changed, truncated or removed AAD, a flipped nonce bit, a flipped key bit, a removed first byte, tag and ciphertext swapped, and inputs of 15 and 0 bytes.
  Wycheproof's invalid entries modify only the tag, so these cover the other changes. Each was confirmed to fail authentication by both oracle implementations.
- The `invalid-key-length` and `invalid-nonce-length` vectors without a source tag use the test case 16 inputs with the stated lengths; `check-order` vectors have two faults and expect the earlier check's error.
- Every expected value was recomputed with two independent implementations and matched its source.

### Long outputs

Wycheproof `seal` results longer than 64 bytes are given as an assertion, to keep this file within the format's 200 KB limit:

```pseudocode
length(result) == N and hex(sha256(result)) == '<64 hex digits>'
```

`length(result)` is in bytes, `sha256` is SHA-256 of the whole result (the `sha-2` spec), and `hex` is lowercase hex. The digest was computed over Wycheproof's `ct || tag`, which was recomputed and matched.

## Edge Cases

- **Empty plaintext.** `seal` returns only the 16-byte tag (GMAC of the AAD); `open` of exactly 16 bytes returns empty bytes when the tag verifies.
- **Sealed input shorter than 16 bytes.** `AuthenticationFailed`, not a length error: it cannot be a valid `seal` output.
- **Empty AAD versus absent AAD.** There is no difference; both are zero-length. Removing the AAD that was sealed is `AuthenticationFailed`.
- **Partial final blocks.** Plaintext and AAD lengths that are not multiples of 16 are zero-padded inside GHASH only; the ciphertext is exactly as long as the plaintext. The (104, 160)-bit NIST vectors and many Wycheproof vectors cover this.
- **Long AAD.** AAD is hashed block by block like the ciphertext; Wycheproof covers AAD lengths up to 513 bytes, and the McGrew-Viega cases 1, 7 and 13 cover empty AAD with an empty plaintext.
- **Nonce of another length.** 0, 8, 11, 13, 16 and 24 bytes are `InvalidNonceLength`, even though SP 800-38D defines GCM for them; the GHASH-derived counter they need is out of scope.
- **Key and nonce both wrong.** `InvalidKeyLength`. A wrong nonce with an empty `sealed` is `InvalidNonceLength`.
- **Plaintext too long.** A plaintext of `2^36 - 31` bytes or more is `PlaintextTooLong`. No vector reaches the limit: the shortest such plaintext is 64 GiB.
- **Wrong key.** Indistinguishable from tampering: `AuthenticationFailed`.

## Implementation Notes

- **Tag check before decryption.** The simplest way to meet the no-release contract is to compute the tag over the ciphertext first, compare, and decrypt only on success. Both passes read the same ciphertext, so the extra cost is one more pass over memory.
- **Constant-time GHASH.** With a carry-less multiply instruction, multiply the 128-bit values as two 64-bit halves (Karatsuba) and reduce modulo the GCM polynomial; mind GCM's reflected bit order (either byte-reverse the inputs or use the reflected reduction).
  Without one, use integer multiplications with masked bits ("multiplication with holes": keep every fourth bit of each operand so carries cannot cross into used bits), or the masked bitwise loop above. The 4-bit table method is fast but leaks `H` through cache timing.
- **Bit order.** GCM numbers bits from the most significant bit of byte 0. Implementations that treat the block as a little-endian integer must byte-reverse, and the reduction constant `e1` then moves to the other end. Test case 2 (one zero block) is the quickest check.
- **Length block.** The final GHASH block holds the AAD length and then the ciphertext length, each as a 64-bit big-endian count of BITS, not bytes.
- **Counter.** `inc32` increments only the last 32 bits. The first plaintext block uses `J0 + 1`; `J0` itself encrypts the tag. Using `J0` for the first block is a common bug that every non-empty vector catches.
- **Nonce reuse.** Repeating a nonce under one key is catastrophic for GCM. Callers SHOULD use a counter or a protocol-defined nonce (as TLS 1.3 does); random 96-bit nonces are safe only for well under 2^32 messages per key.
