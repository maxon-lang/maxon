## Overview

This spec defines the key derivations of TLS 1.2 (RFC 5246) for the ECDHE suites with AEAD ciphers, as six functions:

- **prf** -- `PRF(secret, label, seed)` = `P_hash(secret, label || seed)` with HMAC-SHA-256 or HMAC-SHA-384.
- **master_secret** -- the RFC 5246 section 8.1 master secret from the pre-master secret and the two hello randoms.
- **extended_master_secret** -- the RFC 7627 master secret bound to the session hash.
- **key_block** -- the write keys and implicit IVs of RFC 5246 section 6.3 for an AEAD suite.
- **finished_verify_data** -- the 12-byte `verify_data` of a Finished message.
- **handshake_hash** -- the hash of a sequence of handshake messages with the suite's PRF hash.

HMAC is the `hmac` spec. The `tls12-handshake` spec says when each function is used.

**Out of scope:** the TLS 1.0 and 1.1 PRF (MD5 and SHA-1), CBC and stream suites and their MAC keys, RSA and DHE key exchange, PRF hashes other than SHA-256 and SHA-384, session resumption, keying material exporters (RFC 5705), and TLS 1.3 (the `tls13-key-schedule` spec).

## Types

### Cipher suites

`cipher_suite` is one of six exact strings:

| `cipher_suite` | Code | PRF hash | `Hash.length` | Key | IV (`fixed_iv_length`) |
|---|---|---|---|---|---|
| `"TLS_ECDHE_ECDSA_WITH_AES_128_GCM_SHA256"` | 0xC02B | SHA-256 | 32 | 16 | 4 |
| `"TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256"` | 0xC02F | SHA-256 | 32 | 16 | 4 |
| `"TLS_ECDHE_ECDSA_WITH_AES_256_GCM_SHA384"` | 0xC02C | SHA-384 | 48 | 32 | 4 |
| `"TLS_ECDHE_RSA_WITH_AES_256_GCM_SHA384"` | 0xC030 | SHA-384 | 48 | 32 | 4 |
| `"TLS_ECDHE_ECDSA_WITH_CHACHA20_POLY1305_SHA256"` | 0xCCA9 | SHA-256 | 32 | 32 | 12 |
| `"TLS_ECDHE_RSA_WITH_CHACHA20_POLY1305_SHA256"` | 0xCCA8 | SHA-256 | 32 | 32 | 12 |

### PrfError

```pseudocode
type PrfError =
  | UnsupportedAlgorithm         // prf: hash is not "sha256" or "sha384"
  | UnsupportedCipherSuite       // cipher_suite is not one of the six names above
  | InvalidLabel                 // a label is empty or not printable ASCII
  | InvalidPreMasterSecretLength // the pre-master secret is empty
  | InvalidRandomLength          // a hello random is not 32 bytes
  | InvalidSessionHashLength     // the session hash is not Hash.length bytes
  | InvalidMasterSecretLength    // the master secret is not 48 bytes
  | InvalidSender                // sender is not "client" or "server"
  | InvalidHandshakeHashLength   // the handshake hash is not Hash.length bytes
```

### KeyBlock

```pseudocode
type KeyBlock = { client_write_key: Bytes, server_write_key: Bytes, client_write_iv: Bytes, server_write_iv: Bytes }
```

## Functions

### prf

```pseudocode
prf(hash: String, secret: Bytes, label: String, seed: Bytes, length: Int) -> Bytes | PrfError
```

**Parameters:**

| Name | Type | Required | Description |
|---|---|---|---|
| `hash` | String | yes | `"sha256"` or `"sha384"` |
| `secret` | Bytes | yes | Any length, including 0 |
| `label` | String | yes | 1 or more printable ASCII characters (0x20 to 0x7E), no terminating NUL |
| `seed` | Bytes | yes | Any length, including 0 |
| `length` | Int | yes | Number of output bytes, 0 or more |

**Algorithm:**

1. Check `hash` (`UnsupportedAlgorithm`), then `label` (`InvalidLabel`).
2. `s = label || seed`; `A(0) = s`; `A(i) = HMAC(hash, secret, A(i-1))`.
3. Output `HMAC(secret, A(1) || s) || HMAC(secret, A(2) || s) || ...`, truncated to `length` bytes.

### master_secret

```pseudocode
master_secret(cipher_suite: String, pre_master_secret: Bytes, client_random: Bytes, server_random: Bytes) -> Bytes | PrfError
```

`prf(Hash, pre_master_secret, "master secret", client_random || server_random, 48)`. Checks in order: suite, `InvalidPreMasterSecretLength` (empty), `InvalidRandomLength` for each random. A TLS 1.2 handshake uses it when the peer does not negotiate the extended master secret (the `tls12-handshake` spec).

### extended_master_secret

```pseudocode
extended_master_secret(cipher_suite: String, pre_master_secret: Bytes, session_hash: Bytes) -> Bytes | PrfError
```

`prf(Hash, pre_master_secret, "extended master secret", session_hash, 48)` (RFC 7627 section 4). `session_hash` is `handshake_hash` of every handshake message from ClientHello up to and including ClientKeyExchange. Checks: suite, `InvalidPreMasterSecretLength`, `InvalidSessionHashLength`. For ECDHE the pre-master secret is the raw shared secret: the X25519 output or the P-256 x-coordinate, 32 bytes, leading zeros kept.

### key_block

```pseudocode
key_block(cipher_suite: String, master_secret: Bytes, client_random: Bytes, server_random: Bytes) -> KeyBlock | PrfError
```

`kb = prf(Hash, master_secret, "key expansion", server_random || client_random, 2 * key + 2 * iv)` -- note the server random first. Split in order: `client_write_key`, `server_write_key`, `client_write_iv`, `server_write_iv`. AEAD suites have no MAC keys. Checks: suite, `InvalidMasterSecretLength`, `InvalidRandomLength`.

### finished_verify_data

```pseudocode
finished_verify_data(cipher_suite: String, master_secret: Bytes, sender: String, handshake_hash: Bytes) -> Bytes | PrfError
```

`prf(Hash, master_secret, L, handshake_hash, 12)` with `L` = `"client finished"` or `"server finished"`. `handshake_hash` covers every handshake message before this Finished: up to the client's ClientKeyExchange (or CertificateVerify) for the client, and up to the client Finished for the server. Checks: suite, `InvalidMasterSecretLength`, `InvalidSender`, `InvalidHandshakeHashLength`.

### handshake_hash

```pseudocode
handshake_hash(cipher_suite: String, messages: [Bytes]) -> Bytes | PrfError
```

The PRF hash of the concatenated messages, each a complete handshake message with its 4-byte header. HelloRequest messages are never included. The only error is `UnsupportedCipherSuite`.

## Behavioral Contracts

**MUST:**

1. MUST check arguments in the order each function lists and return the first failure.
2. MUST use the suite's PRF hash -- SHA-384 for the two `_SHA384` suites, SHA-256 otherwise -- for the PRF, the session hash and the handshake hash.
3. MUST put `client_random` first for the master secret and `server_random` first for the key block.
4. MUST NOT include a NUL or a length in the label.
5. MUST return exactly `length` bytes from `prf`; a longer request repeats no block.

## Edge Cases

- **`length` 0** returns empty bytes and computes nothing.
- **Empty secret or seed** are legal PRF inputs: HMAC with an empty key.
- **A secret longer than the hash block** is hashed first by HMAC.
- **The key block of a ChaCha20-Poly1305 suite** has 12-byte IVs (RFC 7905); of an AES-GCM suite, 4-byte implicit IVs (RFC 5288).
- **NIST CAVS randoms.** The SP 800-135 vectors use one pair of randoms for the master secret and another for the key block; real handshakes use the same pair.

## Implementation Notes

- **One P_hash.** `master_secret`, `extended_master_secret`, `key_block` and `finished_verify_data` are all `prf` calls with fixed labels.
- **Session hash timing.** RFC 7627 hashes through ClientKeyExchange, before the master secret exists; compute it then, not at Finished time.
- **Finished compares in constant time** (the `hmac` spec's `constant_time_equal`).
