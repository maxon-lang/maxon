## Overview

This spec defines the TLS 1.3 key schedule of RFC 8446 section 7 for a full (EC)DHE handshake without a pre-shared key, as eight functions:

- **hkdf_expand_label** -- `HKDF-Expand-Label(Secret, Label, Context, Length)`.
- **derive_secret** -- `Derive-Secret(Secret, Label, Messages)`, given the transcript hash of `Messages`.
- **transcript_hash** -- the hash of a sequence of handshake messages.
- **message_hash** -- the synthetic `message_hash` handshake message that replaces the first ClientHello after a HelloRetryRequest.
- **key_schedule** -- the whole secret ladder from the (EC)DHE shared secret: early, handshake and master secrets, the four traffic secrets and the exporter master secret.
- **traffic_keys** -- the AEAD key and IV of a traffic secret.
- **finished_verify_data** -- the `verify_data` of a Finished message.
- **next_application_traffic_secret** -- the KeyUpdate step `application_traffic_secret_N+1`.

HKDF is the `hkdf` spec, HMAC the `hmac` spec and the hashes the `sha-2` spec. Record protection with the keys is the `tls-record` spec; which transcript is hashed at each point of a handshake is the `tls-handshake` spec.

**Out of scope:** pre-shared keys and resumption (`res binder`, `ext binder`, `res master`, `resumption`), 0-RTT (`c e traffic`, `e exp master`), the TLS exporter function itself (RFC 8446 section 7.5; only `exporter_master_secret` is derived), cipher suites other than the three below, and TLS 1.2 (the `tls12-prf` spec).

## Types

### Cipher suites

`cipher_suite` is one of three exact strings. `Hash` is the suite's hash and `Hash.length` its output size:

| `cipher_suite` | Code | Hash | `Hash.length` | AEAD key | IV |
|---|---|---|---|---|---|
| `"TLS_AES_128_GCM_SHA256"` | 0x1301 | SHA-256 | 32 | 16 | 12 |
| `"TLS_AES_256_GCM_SHA384"` | 0x1302 | SHA-384 | 48 | 32 | 12 |
| `"TLS_CHACHA20_POLY1305_SHA256"` | 0x1303 | SHA-256 | 32 | 32 | 12 |

A statically typed implementation SHOULD use an enumeration; the `UnsupportedCipherSuite` vectors are then compile-time rejections.

### KeyScheduleError

```pseudocode
type KeyScheduleError =
  | UnsupportedCipherSuite      // cipher_suite is not one of the three names above
  | InvalidSecretLength         // a secret, traffic secret or base key is not Hash.length bytes
  | InvalidLabel                // a label is empty, longer than 249 bytes, or not printable ASCII
  | ContextTooLong              // a context is longer than 255 bytes
  | OutputTooLong               // length > 255 * Hash.length
  | InvalidTranscriptHashLength // a transcript hash is not Hash.length bytes
  | InvalidSharedSecretLength   // the (EC)DHE shared secret is empty
```

### Secrets

```pseudocode
type Secrets = {
  early_secret: Bytes,
  handshake_secret: Bytes,
  client_handshake_traffic_secret: Bytes,
  server_handshake_traffic_secret: Bytes,
  master_secret: Bytes,
  client_application_traffic_secret_0: Bytes,
  server_application_traffic_secret_0: Bytes,
  exporter_master_secret: Bytes,
}
```

Every field is `Hash.length` bytes.

### TrafficKeys

```pseudocode
type TrafficKeys = { key: Bytes, iv: Bytes }
```

## Functions

### hkdf_expand_label

```pseudocode
hkdf_expand_label(cipher_suite: String, secret: Bytes, label: String, context: Bytes, length: Int) -> Bytes | KeyScheduleError
```

**Parameters:**

| Name | Type | Required | Description |
|---|---|---|---|
| `cipher_suite` | String | yes | Selects `Hash` |
| `secret` | Bytes | yes | `Hash.length` bytes |
| `label` | String | yes | The label without the `"tls13 "` prefix, 1 to 249 printable ASCII characters (0x20 to 0x7E) |
| `context` | Bytes | yes | 0 to 255 bytes |
| `length` | Int | yes | 0 to `255 * Hash.length` |

**Algorithm:**

1. Check, in this order: `cipher_suite` (`UnsupportedCipherSuite`), `length(secret) == Hash.length` (`InvalidSecretLength`), `label` (`InvalidLabel`), `length(context) <= 255` (`ContextTooLong`), `length <= 255 * Hash.length` (`OutputTooLong`).
2. `full_label = "tls13 " || label` (ASCII bytes).
3. `HkdfLabel = uint16(length) || uint8(length(full_label)) || full_label || uint8(length(context)) || context`.
4. Return `HKDF-Expand(Hash, secret, HkdfLabel, length)`.

### derive_secret

```pseudocode
derive_secret(cipher_suite: String, secret: Bytes, label: String, transcript_hash: Bytes) -> Bytes | KeyScheduleError
```

`hkdf_expand_label(cipher_suite, secret, label, transcript_hash, Hash.length)`. The checks are those of `hkdf_expand_label` for the suite, the secret and the label, then `length(transcript_hash) == Hash.length` (`InvalidTranscriptHashLength`). RFC 8446 writes the third argument as `Messages`; this function takes `Transcript-Hash(Messages)`, which `transcript_hash` computes.

### transcript_hash

```pseudocode
transcript_hash(cipher_suite: String, messages: [Bytes]) -> Bytes | KeyScheduleError
```

`Hash(messages[0] || messages[1] || ...)`. Each element is a complete handshake message with its 4-byte header (type and 24-bit length), as sent; no record headers. An empty list hashes the empty string. The only error is `UnsupportedCipherSuite`.

### message_hash

```pseudocode
message_hash(cipher_suite: String, client_hello: Bytes) -> Bytes | KeyScheduleError
```

The 4 + `Hash.length` byte message `0xFE || 0x00 || 0x00 || uint8(Hash.length) || Hash(client_hello)` (RFC 8446 section 4.4.1). After a HelloRetryRequest the transcript begins `message_hash(ClientHello1), HelloRetryRequest, ClientHello2, ...`. The only error is `UnsupportedCipherSuite`.

### key_schedule

```pseudocode
key_schedule(cipher_suite: String, shared_secret: Bytes, hello_hash: Bytes, server_finished_hash: Bytes) -> Secrets | KeyScheduleError
```

**Parameters:**

| Name | Type | Required | Description |
|---|---|---|---|
| `shared_secret` | Bytes | yes | The (EC)DHE shared secret, at least 1 byte (32 for X25519 and for P-256) |
| `hello_hash` | Bytes | yes | Transcript hash of ClientHello ... ServerHello |
| `server_finished_hash` | Bytes | yes | Transcript hash of ClientHello ... server Finished |

**Algorithm** (`N = Hash.length`, `Z = N` zero bytes, `E = Hash("")`):

1. Check `cipher_suite`, then `length(shared_secret) >= 1` (`InvalidSharedSecretLength`), then each hash length (`InvalidTranscriptHashLength`).
2. `early_secret = HKDF-Extract(salt = Z, ikm = Z)`.
3. `handshake_secret = HKDF-Extract(salt = HKDF-Expand-Label(early_secret, "derived", E, N), ikm = shared_secret)`.
4. `client_handshake_traffic_secret = HKDF-Expand-Label(handshake_secret, "c hs traffic", hello_hash, N)`; `server_handshake_traffic_secret` likewise with `"s hs traffic"`.
5. `master_secret = HKDF-Extract(salt = HKDF-Expand-Label(handshake_secret, "derived", E, N), ikm = Z)`.
6. `client_application_traffic_secret_0`, `server_application_traffic_secret_0` and `exporter_master_secret` are `HKDF-Expand-Label(master_secret, L, server_finished_hash, N)` with `L` = `"c ap traffic"`, `"s ap traffic"` and `"exp master"`.

### traffic_keys

```pseudocode
traffic_keys(cipher_suite: String, traffic_secret: Bytes) -> TrafficKeys | KeyScheduleError
```

`key = HKDF-Expand-Label(traffic_secret, "key", "", key_length)` and `iv = HKDF-Expand-Label(traffic_secret, "iv", "", 12)`, with the key length of the table. Checks: suite, then `InvalidSecretLength`.

### finished_verify_data

```pseudocode
finished_verify_data(cipher_suite: String, base_key: Bytes, transcript_hash: Bytes) -> Bytes | KeyScheduleError
```

`finished_key = HKDF-Expand-Label(base_key, "finished", "", N)`; return `HMAC(Hash, finished_key, transcript_hash)`. `base_key` is the sender's handshake traffic secret. For the server Finished the transcript runs from ClientHello to the server CertificateVerify; for the client Finished, from ClientHello to the server Finished (plus the client's Certificate and CertificateVerify when it sends them). Checks: suite, `InvalidSecretLength`, `InvalidTranscriptHashLength`.

### next_application_traffic_secret

```pseudocode
next_application_traffic_secret(cipher_suite: String, secret: Bytes) -> Bytes | KeyScheduleError
```

`HKDF-Expand-Label(secret, "traffic upd", "", N)` (RFC 8446 section 7.2). Checks: suite, `InvalidSecretLength`.

## Behavioral Contracts

**MUST:**

1. MUST check arguments in the order each function lists and return the first failure.
2. MUST encode `HkdfLabel` exactly: a 2-byte length, the label with its 6-byte `"tls13 "` prefix and a 1-byte length, the context with a 1-byte length. The `"derived"` steps use the hash of the empty string as context, not an empty context.
3. MUST use `Hash.length` zero bytes, never an empty value, for the PSK input of the early secret and the IKM of the master secret.
4. MUST derive the handshake traffic secrets from the hash of ClientHello ... ServerHello and the application traffic secrets and exporter master secret from the hash of ClientHello ... server Finished.
5. MUST compute every value of a suite with that suite's hash: SHA-384 for `TLS_AES_256_GCM_SHA384`, SHA-256 for the others.
6. MUST hash handshake messages exactly as they were sent or received, headers included, and, after a HelloRetryRequest, MUST replace the first ClientHello with `message_hash` of it.

**SHOULD:**

1. SHOULD erase each secret once the next one in the ladder and its traffic keys exist.

## Test Vectors

Binary arguments and results are lowercase hex in `*_hex` fields. `messages_hex` is a list. `key_schedule` and `traffic_keys` return objects whose fields are the `Secrets` and `TrafficKeys` names with `_hex` appended.

### Sources

- `rfc8448` vectors (87) are transcribed from RFC 8448 sections 3 to 7: every `derive secret` step (as `derive_secret` when the context is a transcript hash, otherwise `hkdf_expand_label`, with label and context read from the printed HkdfLabel), every traffic key and IV, every Finished and the section 4 PSK binder (`finished_verify_data`, with the transcript hash recomputed
  from the printed messages), the transcript hashes at the two derivation points, `message_hash` of section 5, and `key_schedule` for sections 3, 5, 6 and 7 (section 4 uses a PSK). The early, handshake and master secrets and the traffic secrets are the printed values.
- `openssl` vectors (36) come from TLS 1.3 handshakes between the reference client or server and OpenSSL 3.0.13 (the `ssl` module of Python 3.11.9, memory BIOs): `key_schedule` with the shared secret and transcript hashes of the handshake, and `traffic_keys` of its secrets. The two handshake and two application traffic secrets and the exporter master secret equal OpenSSL's key
  log (`CLIENT_HANDSHAKE_TRAFFIC_SECRET`, `SERVER_HANDSHAKE_TRAFFIC_SECRET`, `CLIENT_TRAFFIC_SECRET_0`, `SERVER_TRAFFIC_SECRET_0`, `EXPORTER_SECRET`); the early, handshake and master secrets are not logged.
- `generated` vectors (44) cover SHA-384 and ChaCha20-Poly1305 suites, boundary lengths, `next_application_traffic_secret`, and the errors. No published vector exists for `traffic upd`; those vectors rest on the two HKDF implementations and on the KeyUpdate handshake vectors of the `tls-handshake` spec.
- RFC 8448 itself was verified, not trusted: `rfc8448_check.py` recomputes every ephemeral public key, shared secret, HKDF step, traffic key, Finished, CertificateVerify signature (RSA-PSS and ECDSA, pure and pyca) and protected record of sections 3 to 7, and replays the client of sections 3, 5 and 7 byte for byte (exit 0).
- Every vector was re-checked from this file by `check_specs.py` twice: with the pure-Python primitives (`purecore.py`: HMAC, HKDF, AES-GCM, ChaCha20-Poly1305, X25519, P-256, ECDSA, RSA, Ed25519, written from their standards) and with pyca/cryptography 50.0.2 primitives under the same TLS logic. Both runs reproduce every expected value.

## Edge Cases

- **`length` 0** returns empty bytes (HKDF-Expand of zero bytes).
- **The longest label** is 249 characters: `"tls13 "` plus 249 bytes fills the 255-byte limit of the label vector.
- **Context of 255 bytes** is allowed; 256 is `ContextTooLong`.
- **A shared secret shorter than 32 bytes** is accepted; only the empty one is refused. X25519 and P-256 always give 32 bytes.
- **SHA-384 suite with a 32-byte secret** is `InvalidSecretLength`, not silently accepted; mixing suites is the commonest key schedule bug.
- **HelloRetryRequest.** `message_hash` uses the hash of the suite the HelloRetryRequest selected.
- **Several KeyUpdates.** Each update applies `next_application_traffic_secret` to the previous output.

## Implementation Notes

- **One function, many labels.** Every derivation is `hkdf_expand_label`; build the label once with its prefix and length.
- **Transcript hashing.** Keep a running hash (the `sha-2` spec's incremental digest) and take snapshots; do not rehash the whole transcript at each step.
- **Context is a hash, not the messages.** `derive_secret` hashes; passing the raw messages as context is a frequent mistake that RFC 8448's vectors catch.
- **Do not truncate.** `Hash.length` is 48 for `TLS_AES_256_GCM_SHA384`: every secret, the Finished `verify_data` and the transcript hash are 48 bytes there.
- **Finished compares in constant time** (the `hmac` spec's `constant_time_equal`).
