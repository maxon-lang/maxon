## Overview

This spec defines the X25519 function of RFC 7748 section 5, scalar multiplication on the Montgomery form of Curve25519 using only u-coordinates, and the Diffie-Hellman use of it in section 6.1, as two functions:

- **x25519** -- multiplies the point with u-coordinate `u_coordinate` by the clamped `scalar` and returns the resulting u-coordinate. With a peer's public key as `u_coordinate` and one's own private key as `scalar`, the result is the shared secret.
- **public_key** -- returns `x25519(private_key, 9)`, the u-coordinate of the clamped private key times the base point.

`x25519` rejects an all-zero result with `AllZeroSharedSecret`. RFC 7748 section 6.1 makes that check optional (MAY); TLS 1.3 (RFC 8446 section 7.4.2) makes it mandatory, and this spec follows TLS: an all-zero output is never returned. It arises exactly when `u_coordinate` encodes a point whose order divides the cofactor 8 (or such a point plus a multiple of `p`), which lets a peer force a known shared secret.

**Out of scope:** X448; key generation (the private key is any 32 bytes, normally from a secure random source, the `secure-random-bytes` spec); the key derivation that follows the exchange (the `hkdf` spec); Edwards-form arithmetic and Ed25519 (the `ed25519-verify` spec); conversion between Ed25519 and X25519 keys; rejecting public keys on the twist or with non-canonical encodings, which RFC 7748 accepts.

## Types

### X25519Error

```pseudocode
type X25519Error =
  | InvalidLength         // a scalar, u-coordinate or private key is not exactly 32 bytes
  | AllZeroSharedSecret   // x25519 only: the result is 32 zero bytes (a low-order u-coordinate)
```

### Constants and encodings

| Name | Value |
|---|---|
| `p` | `2^255 - 19`, the field prime |
| `a24` | `121665`, that is `(486662 - 2) / 4` for the curve `v^2 = u^3 + 486662 u^2 + u` |
| Base point u-coordinate | `9`, encoded as the byte `09` followed by 31 zero bytes |
| Scalar, u-coordinate, private key, result | exactly 32 bytes each, little-endian |

```pseudocode
decode_scalar(k: 32 bytes) -> Int:
  b = copy of k
  b[0]  = b[0]  AND 248       // clear the 3 low bits: a multiple of the cofactor 8
  b[31] = b[31] AND 127       // clear bit 255
  b[31] = b[31] OR  64        // set bit 254
  return b as a little-endian integer

decode_u_coordinate(u: 32 bytes) -> Int:
  b = copy of u
  b[31] = b[31] AND 127       // bit 255 is ignored
  return b as a little-endian integer   // MAY be >= p; it is used mod p

encode_u_coordinate(x: Int) -> 32 bytes:
  return (x mod p) as 32 little-endian bytes
```

## Functions

### x25519

```pseudocode
x25519(scalar: Bytes, u_coordinate: Bytes) -> Bytes | X25519Error
```

**Parameters:**

| Name | Type | Required | Description |
|---|---|---|---|
| `scalar` | Bytes | yes | Exactly 32 bytes; a private key. It is clamped by `decode_scalar`, so every 32-byte string is valid |
| `u_coordinate` | Bytes | yes | Exactly 32 bytes; a public key. Bit 255 is ignored and values `>= p` are reduced, so every 32-byte string is valid input |

**Returns:** the 32-byte u-coordinate of `decode_scalar(scalar) * U`, or `InvalidLength`, or `AllZeroSharedSecret`.

**Algorithm:**

1. If `length(scalar) != 32` or `length(u_coordinate) != 32`, return `InvalidLength`.
2. `k = decode_scalar(scalar)`; `x_1 = decode_u_coordinate(u_coordinate)`.
3. Run the Montgomery ladder below, giving `x_2` and `z_2`.
4. `result = encode_u_coordinate(x_2 * z_2^(p - 2))`. When `z_2 = 0` this gives 0.
5. If every byte of `result` is zero, compared in constant time, return `AllZeroSharedSecret`.
6. Return `result`.

The ladder is RFC 7748 section 5 exactly. All arithmetic is modulo `p`:

```pseudocode
x_2 = 1; z_2 = 0; x_3 = x_1; z_3 = 1; swap = 0
for t = 254 down to 0:
  k_t = (k >> t) AND 1
  swap = swap XOR k_t
  (x_2, x_3) = cswap(swap, x_2, x_3)
  (z_2, z_3) = cswap(swap, z_2, z_3)
  swap = k_t
  A  = x_2 + z_2;  AA = A^2
  B  = x_2 - z_2;  BB = B^2
  E  = AA - BB
  C  = x_3 + z_3
  D  = x_3 - z_3
  DA = D * A
  CB = C * B
  x_3 = (DA + CB)^2
  z_3 = x_1 * (DA - CB)^2
  x_2 = AA * BB
  z_2 = E * (AA + a24 * E)
(x_2, x_3) = cswap(swap, x_2, x_3)
(z_2, z_3) = cswap(swap, z_2, z_3)

cswap(swap, a, b):              // swap is 0 or 1; no branch
  mask  = 0 - swap              // all zero bits or all one bits
  dummy = mask AND (a XOR b)
  return (a XOR dummy, b XOR dummy)
```

### public_key

```pseudocode
public_key(private_key: Bytes) -> Bytes | X25519Error
```

**Parameters:**

| Name | Type | Required | Description |
|---|---|---|---|
| `private_key` | Bytes | yes | Exactly 32 bytes; clamped as `decode_scalar` does |

**Returns:** the 32-byte public key, or `InvalidLength`.

**Algorithm:**

1. If `length(private_key) != 32`, return `InvalidLength`.
2. Return `x25519(private_key, 09 00 00 ... 00)`.

`public_key` never returns `AllZeroSharedSecret`: the base point has prime order `2^252 + 27742317777372353535851937790883648493`, and a clamped scalar is never a multiple of it, so the result is never the point at infinity.

## Behavioral Contracts

### x25519()

**MUST:**

1. MUST return the RFC 7748 section 5 output for every pair of 32-byte inputs whose output is not all zero.
2. MUST check both lengths before computing anything, and MUST return `InvalidLength` rather than truncate, pad or hash an input.
3. MUST clamp the scalar as `decode_scalar` does: the caller's bits 0, 1, 2 and 255 have no effect, and bit 254 is always set.
4. MUST ignore bit 255 of `u_coordinate`, and MUST accept a u-coordinate in `[p, 2^255 - 1]` as the same value reduced mod `p` (RFC 7748 section 5: "implementations of X25519 MUST mask the most significant bit" and MUST accept non-canonical values).
5. MUST accept a u-coordinate on the quadratic twist and return the ladder's output for it; it MUST NOT check that the point is on the curve.
6. MUST return `AllZeroSharedSecret` when the computed output is 32 zero bytes, and MUST NOT return that output (RFC 8446 section 7.4.2). The check MUST be made on the encoded output, by ORing its 32 bytes together and testing the result once, so that it takes the same time for every output.
7. MUST run in constant time with respect to `scalar` and the intermediate values:
   - exactly 255 ladder steps for every scalar, whatever its leading bits;
   - the conditional swap done with a mask (`cswap` above), never with a branch or a secret-indexed memory access;
   - field arithmetic whose running time and memory accesses do not depend on the operands, including the final reduction to `[0, p)`;
   - the inversion done as `z_2^(p - 2)` with a fixed addition chain, or another method that does not branch on `z_2`.
   The input lengths are not secret.
8. MUST NOT modify its inputs.

**SHOULD:**

1. SHOULD overwrite the decoded scalar and the ladder state before returning.

### public_key()

**MUST:**

1. MUST return exactly `x25519(private_key, 9)` for every 32-byte `private_key`.
2. MUST return `InvalidLength` for any other length.
3. MUST meet the constant-time contract of `x25519`; the private key is secret.

The caller SHOULD treat `AllZeroSharedSecret` as a fatal handshake error (TLS 1.3 requires the handshake to abort), and MUST derive keys from the shared secret with a KDF rather than use it directly.

## Test Vectors

`scalar_hex`, `u_coordinate_hex` and `private_key_hex` are lowercase hex. Expected output is `result_hex`, 32 bytes.

### Sources

- `rfc7748-5-2` vectors are the two X25519 test vectors of RFC 7748 section 5.2. The second has bit 255 of its u-coordinate set (`high-bit-set`).
- `rfc7748-6-1` vectors are the Diffie-Hellman example of section 6.1: Alice's and Bob's public keys as `x25519(private, 9)` and as `public_key(private)`, and the shared secret computed by each side.
- `iterated` vectors are the iteration test of section 5.2. Start with `k = u = 09 00 .. 00`; each iteration sets `(k, u) = (x25519(k, u), k)`. The RFC publishes `k` after 1, 1000 and 1000000 iterations. Each vector is the LAST call of the loop: its `scalar_hex` and `u_coordinate_hex` are `k` and `u` after 0, 999 and 999999 iterations (computed by running the loop), and its result is the published value. The full loop is in Implementation Notes.
- `wycheproof-tc-N` vectors are from Project Wycheproof `testvectors_v1/x25519_test.json` (test-case id `N`; the flag names follow as tags).
  Included: every `valid` entry (264); every entry with an all-zero shared secret (31, all flagged `LowOrderPublic` and `ZeroSharedSecret`, `acceptable` in Wycheproof), as `AllZeroSharedSecret` errors; and every other `acceptable` entry except those flagged `EdgeCaseMultiplication` (53: twist points, special and non-canonical public keys, edge-case shared values and one known-answer test).
  The 170 `acceptable` entries flagged `EdgeCaseMultiplication` are twist points that exercise the same ladder edge cases as the 219 `valid` entries with that flag, and are left out to keep this file within the format's 200 KB limit; all 170 were recomputed and matched.
- `computed` vectors have no published source: `public_key` of the all-zero, all-ones and clamping-equivalent private keys, and the `AllZeroSharedSecret` results for `u = 0` and `u = 1`.
- The `invalid-length` vectors follow from the length rule; `check-order` gives a wrong-length scalar with the low-order point `u = 0` and expects `InvalidLength`.
- Every expected value was recomputed with two independent implementations (a transcription of the RFC 7748 ladder and a production library) and matched its source; the 1000000-iteration value was reproduced by running the loop.

## Edge Cases

- **Low-order points.** After masking bit 255 there are seven: `u = 0`, `u = 1`, the two u-coordinates of points of order 8 (encoded `e0eb7a7c...b800` and `5f9c95bc...1157`), `u = p - 1` (order 2), and the non-canonical `u = p` and `u = p + 1` (the same values as 0 and 1). Each gives 32 zero bytes for every scalar, because the clamped scalar is a multiple of 8, and the same holds with bit 255 set. All are `AllZeroSharedSecret`; Wycheproof covers all fourteen encodings.
- **Bit 255 of the u-coordinate.** Ignored: `u` and `u OR 2^255` give the same result. RFC 7748 5.2 vector 2 and many Wycheproof vectors have it set.
- **Non-canonical u-coordinate.** A value in `[p, 2^255 - 1]` (19 such values after masking) is used mod `p`, not rejected.
- **Twist points.** A u-coordinate that is not on Curve25519 lies on its twist; the ladder still produces a value and it is returned. The twist's cofactor is 4, so its low-order points also give zero.
- **Scalar bits.** Two scalars that differ only in bits 0, 1, 2 or 255, or in bit 254 when it is clear in one of them, give the same output.
- **Base point.** `x25519(k, 9)` equals `public_key(k)`; the 1-iteration vector is `x25519(9, 9)`.
- **Wrong lengths.** 0, 31, 33 and 64 bytes for either argument are `InvalidLength`; the length check comes before any computation, including the all-zero check.

## Implementation Notes

- **Field representation.** Common choices are five 51-bit limbs (64-bit targets with a 64x64->128 multiply) or ten limbs of alternating 26 and 25 bits (32-bit targets). Carries must be propagated without branches, and the final `encode_u_coordinate` must reduce fully into `[0, p)` with a constant-time conditional subtraction of `p`; a partially reduced output is the most common defect, and the `non-canonical-public` Wycheproof vectors catch it.
- **The ladder's `x_1`.** The ladder uses `x_1` reduced mod `p`; with a limb representation that accepts values up to `2^255 - 1`, loading the masked 255 bits directly is enough, as long as every operation tolerates an unreduced input.
- **Inversion.** `z^(p-2)` by the standard chain of 254 squarings and 11 multiplications is constant time. Binary extended Euclid is not, unless written for constant time.
- **Zero check.** OR the 32 output bytes into one byte and test it once, after the full reduction. A comparison that stops at the first non-zero byte leaks how many low bytes of the secret are zero.
- **Iteration test.** In pseudocode: `k = 09 00..00; u = 09 00..00; repeat n times: (k, u) = (x25519(k, u), k)`. After 1 iteration `k = 422c8e7a...3079`, after 1000 `k = 684cf59b...2c51`, after 1000000 `k = 7c3911e0...5424` (RFC 7748 section 5.2). The 1000-iteration run is a cheap whole-ladder regression test.
- **Little-endian everywhere.** Scalars, u-coordinates and results are little-endian; a big-endian load reverses every vector.
- **Use of the result.** The shared secret is a u-coordinate, not a uniformly random key; feed it, together with the transcript, to a KDF.
