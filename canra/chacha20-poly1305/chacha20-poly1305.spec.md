## Overview

This spec defines AEAD_CHACHA20_POLY1305, the authenticated encryption with associated data (AEAD) of RFC 8439 section 2.8, with a 256-bit key, a 96-bit nonce and a 128-bit tag:

- **seal** -- encrypts a plaintext and authenticates it together with associated data (AAD), returning the ciphertext followed by the tag.
- **open** -- verifies the tag and, only if it is valid, returns the plaintext.

The `seal`/`open` contract is common to AEADs (RFC 5116): `seal(key, nonce, plaintext, aad)` returns RFC 5116's ciphertext (the encrypted plaintext with the tag appended), and `open` returns the plaintext or a single authentication failure. The `aes-gcm` spec has the same shape and the same `AeadError` type. The cipher is the `chacha20` spec's `xor_key_stream` and the block function it defines; the authenticator is the `poly1305` spec's `mac`.

**Out of scope:** XChaCha20-Poly1305 (24-byte nonce) and every other nonce length; truncated tags; the original 64-bit-nonce construction; nonce generation; streaming, in-place or detached-tag interfaces.

## Types

### AeadError

```pseudocode
type AeadError =
  | InvalidKeyLength       // the key is not exactly 32 bytes
  | InvalidNonceLength     // the nonce is not exactly 12 bytes
  | PlaintextTooLong       // seal only: the plaintext is longer than 2^38 - 64 bytes
  | AuthenticationFailed   // open only: the sealed input is shorter than 16 bytes, or the tag does not verify
```

`AuthenticationFailed` carries no detail: a modified ciphertext, tag, AAD, nonce or key, a truncated input and an input too short to hold a tag all give the same error.

### Lengths

| Item | Length |
|---|---|
| Key | exactly 32 bytes |
| Nonce | exactly 12 bytes |
| Tag | exactly 16 bytes |
| Plaintext | 0 to `2^38 - 64` bytes (keystream blocks 1 to `2^32 - 1`) |
| AAD | 0 to `2^64 - 1` bytes |
| Sealed output | `length(plaintext) + 16` bytes |

## Functions

### seal

```pseudocode
seal(key: Bytes, nonce: Bytes, plaintext: Bytes, aad: Bytes) -> Bytes | AeadError
```

**Parameters:**

| Name | Type | Required | Description |
|---|---|---|---|
| `key` | Bytes | yes | Exactly 32 bytes |
| `nonce` | Bytes | yes | Exactly 12 bytes; MUST be unique per key |
| `plaintext` | Bytes | yes | Any length from 0 to `2^38 - 64` bytes |
| `aad` | Bytes | yes | Associated data, authenticated but not encrypted; MAY be empty |

**Returns:** `ciphertext || tag`, `length(plaintext) + 16` bytes, or `InvalidKeyLength`, or `InvalidNonceLength`, or `PlaintextTooLong`.

**Algorithm:**

1. If `length(key) != 32`, return `InvalidKeyLength`.
2. If `length(nonce) != 12`, return `InvalidNonceLength`.
3. If `length(plaintext) > 2^38 - 64`, return `PlaintextTooLong`.
4. `otk = first 32 bytes of chacha20_block(key, 0, nonce)` (RFC 8439 section 2.6).
5. `ciphertext = xor_key_stream(key, nonce, 1, plaintext)`.
6. `mac_data = aad || zeros(-length(aad) mod 16) || ciphertext || zeros(-length(ciphertext) mod 16) || le64(length(aad)) || le64(length(ciphertext))`.
7. `tag = mac(otk, mac_data)`.
8. Return `ciphertext || tag`.

### open

```pseudocode
open(key: Bytes, nonce: Bytes, sealed: Bytes, aad: Bytes) -> Bytes | AeadError
```

**Parameters:**

| Name | Type | Required | Description |
|---|---|---|---|
| `key` | Bytes | yes | Exactly 32 bytes |
| `nonce` | Bytes | yes | Exactly 12 bytes, the one given to `seal` |
| `sealed` | Bytes | yes | `ciphertext || tag` as returned by `seal` |
| `aad` | Bytes | yes | The associated data given to `seal` |

**Returns:** The plaintext, `length(sealed) - 16` bytes, or `InvalidKeyLength`, or `InvalidNonceLength`, or `AuthenticationFailed`.

**Algorithm:**

1. If `length(key) != 32`, return `InvalidKeyLength`.
2. If `length(nonce) != 12`, return `InvalidNonceLength`.
3. If `length(sealed) < 16`, return `AuthenticationFailed`.
4. Split `sealed` into `ciphertext` (all but the last 16 bytes) and `tag` (the last 16 bytes).
5. Compute `otk`, `mac_data` and `expected_tag = mac(otk, mac_data)` as `seal` steps 4, 6 and 7 do, over the received `ciphertext`.
6. If `expected_tag != tag`, compared in constant time, return `AuthenticationFailed`.
7. Return `xor_key_stream(key, nonce, 1, ciphertext)`.

## Behavioral Contracts

### seal()

**MUST:**

1. MUST return the RFC 8439 section 2.8 ciphertext and full 16-byte tag, concatenated.
2. MUST check the key length, then the nonce length, then the plaintext length, before computing anything.
3. MUST derive a fresh Poly1305 key from block 0 for every call and encrypt starting at block 1; block 0's remaining 32 bytes are discarded.
4. MUST accept an empty plaintext (the output is the 16-byte tag alone) and empty AAD.
5. MUST return `PlaintextTooLong` for a plaintext longer than `2^38 - 64` bytes; it MUST NOT wrap the block counter.

### open()

**MUST:**

1. MUST check the key length, then the nonce length, then `length(sealed) >= 16`, then the tag, in that order.
2. MUST return `AuthenticationFailed` for every input whose tag does not verify: any change to the ciphertext, the tag, the AAD, the nonce or the key, and any truncation or extension of `sealed`.
3. MUST compare the computed and received tags in constant time: the time taken MUST NOT depend on how many leading bytes match (the `hmac` spec's `constant_time_equal`).
4. MUST NOT release any plaintext when authentication fails: not a partial result, not a buffer the caller can read. The tag is computed over the ciphertext, so the check needs no decryption; decrypt only after it succeeds.
5. MUST return exactly the plaintext `seal` encrypted, for every valid input.

### Common

**MUST:**

1. MUST run in constant time, as the `chacha20` and `poly1305` specs require: no branch on and no memory index derived from the key, the nonce, the data, the AAD or the tag. Lengths are not secret.
2. `open(k, n, seal(k, n, p, a), a) == p` for every valid `k`, `n`, `p` and `a`.

**SHOULD:**

1. SHOULD overwrite the one-time key, the keystream and the expected tag before returning.

The caller MUST NOT seal two different messages with the same key and nonce: a repeated nonce repeats both the keystream and the one-time Poly1305 key, which reveals the XOR of the plaintexts and lets an attacker forge tags. This is a requirement on the caller, not a checkable property of `seal`.

## Test Vectors

Binary arguments are lowercase hex in `key_hex`, `nonce_hex`, `plaintext_hex`, `sealed_hex` and `aad_hex`. A `seal` result is `ciphertext || tag`; an `open` result is the plaintext.

### Sources

- `rfc8439-2-8-2` is the AEAD example of RFC 8439 section 2.8.2; its nonce is the 32-bit constant `07 00 00 00` followed by the 64-bit IV `40 41 .. 47`. `rfc8439-a5` is the decryption example of appendix A.5. Each is a `seal` and an `open` vector.
- `wycheproof-tc-N` vectors are from Project Wycheproof `testvectors_v1/chacha20_poly1305_test.json` (test-case id `N`), with Wycheproof's flags as tags.
  `seal` vectors are every `valid` entry with a 12-byte nonce except the `Pseudorandom` entries whose plaintext or AAD exceeds 64 bytes (27 of the 256 valid entries are left out to keep this file within the format's 200 KB limit); every `EdgeCase*` and `Ktv` entry is included. The `open` vectors from Wycheproof are the included valid entries with an empty plaintext.
  Every `invalid` entry is an `open` vector: those with a 12-byte nonce (all `ModifiedTag`) expect `AuthenticationFailed`, and the `InvalidNonceSize` entries (nonces of 0, 8, 11, 13, 14, 16, 20, 24 and 32 bytes) expect `InvalidNonceLength`.
- `constructed` vectors modify the section 2.8.2 sealed output: a flipped ciphertext bit, a flipped tag bit, changed, truncated or removed AAD, a flipped nonce bit, a flipped key bit, a removed first byte, tag and ciphertext swapped, and inputs of 15 and 0 bytes. Wycheproof's invalid entries modify only the tag, so these cover the other changes.
  Each was confirmed to fail authentication by both oracle implementations.
- The `invalid-key-length` and `invalid-nonce-length` vectors without a source tag use the section 2.8.2 inputs (plaintext shortened to 16 bytes) with the stated lengths; `check-order` vectors have two faults and expect the earlier check's error.
- Every expected value was recomputed with two independent implementations and matched its source.

### Long outputs

Wycheproof `seal` results longer than 64 bytes are given as an assertion, to keep this file within the format's 200 KB limit:

```pseudocode
length(result) == N and hex(sha256(result)) == '<64 hex digits>'
```

`length(result)` is in bytes, `sha256` is SHA-256 of the whole result (the `sha-2` spec), and `hex` is lowercase hex. The digest was computed over Wycheproof's `ct || tag`, which was recomputed and matched.

## Edge Cases

- **Empty plaintext.** `seal` returns only the 16-byte tag; the Poly1305 input is then the padded AAD and the two lengths. `open` of exactly 16 bytes returns empty bytes when the tag verifies.
- **Sealed input shorter than 16 bytes.** `AuthenticationFailed`, not a length error.
- **Padding.** The AAD and the ciphertext are each zero-padded to a multiple of 16 bytes inside the Poly1305 input; nothing is padded when a length is already a multiple of 16 (including zero). The lengths are 64-bit little-endian BYTE counts.
- **Poly1305 arithmetic edges.** The Wycheproof `edge-case-poly1305`, `edge-case-poly-key`, `edge-case-tag` and `edge-case-ciphertext` vectors drive the authenticator into its carry and reduction corner cases through the AEAD.
- **Nonce of another length.** 0, 8, 11, 13, 16 and 24 bytes (and the Wycheproof sizes) are `InvalidNonceLength`; a 24-byte nonce is XChaCha20-Poly1305, which this spec does not implement.
- **Key and nonce both wrong.** `InvalidKeyLength`. A wrong nonce with an empty `sealed` is `InvalidNonceLength`.
- **Plaintext too long.** A plaintext of `2^38 - 63` bytes or more is `PlaintextTooLong`. No vector reaches the limit: the shortest such plaintext is 256 GiB.
- **Wrong key.** Indistinguishable from tampering: `AuthenticationFailed`.

## Implementation Notes

- **Block 0 is the MAC key.** The keystream for the plaintext starts at counter 1. Starting at 0 encrypts with the bytes that became the Poly1305 key and fails every vector.
- **Little-endian lengths.** Unlike GCM, the length block is little-endian and counts bytes. RFC 8439 section 2.8.2 prints the full Poly1305 input, which is the best reference when a tag is wrong.
- **Verify, then decrypt.** The tag covers the ciphertext, so `open` authenticates first and decrypts only on success; no plaintext exists on the failure path.
- **Nonce construction.** Protocols build the 12-byte nonce from a fixed prefix and a counter (RFC 8439 section 2.8.2 uses a 32-bit sender constant and a 64-bit IV; TLS 1.3 XORs a sequence number into a per-connection IV). Random 96-bit nonces are acceptable only for a limited number of messages per key.
- **Constant-time tag comparison.** Compare all 16 bytes with an accumulate-OR loop, never with a byte comparison that stops at the first difference.
