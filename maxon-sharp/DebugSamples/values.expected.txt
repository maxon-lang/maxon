P4a value-inspection gate — reproducible transcript over DebugSamples/values.maxon.

HOW TO REPRODUCE (from a checkout that has built the C# compiler):
  maxon build maxon-sharp/DebugSamples/values.maxon
  maxon debug --batch --commands='break values.maxon:40; run; locals; print person; print person.name; print person.age; print person.active; print person.home; print person.home.name; print person.home.population; print greeting; print missing; print person.bogus' maxon-sharp/DebugSamples/values.exe

WHAT IS STABLE vs ENVIRONMENT-SPECIFIC:
  * The `locals` and `value` event bodies are the P4a subject and are BYTE-STABLE: no heap addresses (a
    struct renders as "{...}" with its fields as children — displayed as the \u2026 ellipsis), no timing,
    no paths. The output is newline-delimited JSON; System.Text.Json escapes " ' < > and non-ASCII as
    \uXXXX, so "hello world" appears as \u0022hello world\u0022, etc.
  * The `stop`/`backtrace` events carry the source path exactly as it was passed to `maxon build` (the
    repo-relative `maxon-sharp/DebugSamples/values.maxon` when built from the repo root as shown above;
    an absolute path if built with one), and two build-specific `.text` offsets (0x258 = the stop PC at
    values.maxon:40, 0x51 = the entry-stub return address). Those come from P3's breakpoint/backtrace
    machinery, not P4a, and move only if codegen for `main` moves.
  * Exit code is 42; the target's own three print calls emit `hello worldAdaPortland` on STDERR in
    --batch mode (stdout stays a clean JSON channel), so they are not part of this stdout transcript.

Coverage exercised here: String (text + length), a struct rendered as a named-field subtree, a bool
field (person.active = true), int fields (person.age = 20, population = 650000), a nested struct
(person.home), dotted path navigation to every leaf, and honest error nodes for an unknown local
(missing) and an unknown field (person.bogus).
