P5 `maxon mcp` gate — the compiler's own MCP server, over HTTP, hosting a LIVE debug session.

⭐ WHAT THIS GOLDEN IS FOR. Every other golden here drives ONE `maxon debug` process from a script it was
given up front. This one proves the thing that made P5 worth doing: an agent that decides what to ask
NEXT from what it just saw. BLOCK 1's two `debug_locals` calls are separate HTTP requests, minutes apart
if the agent likes, and THEY RETURN DIFFERENT VALUES — "before" (len=6) then "after" (len=5), with a
`debug_step` between them. A replayed transcript cannot do that; only a debuggee still parked between two
requests can.

The `maxon mcp` line below is the SERVER: it runs first, in the background, and the four client commands
after it each drive one block against it. (The gate discovers all six the same way every other golden's
commands are discovered — by reading them here, so they exist exactly once.)

WHAT EACH BLOCK PROVES (asserted by the transcripts below):
  * BLOCK 1 — THE HEADLINE, and the design doc's own acceptance line: "agent sets bp, gets stop+locals".
    `debug_start` builds the sample, launches it under the debugger, arms mcp.maxon:19 and runs to it, in
    ONE call; the events it returns are byte-for-byte the events `maxon debug --batch` emits for the same
    script, because they come from the same renderers through the same dispatcher. THEN THE SESSION STAYS
    LIVE: `debug_locals` reads stage="before", `debug_step` runs line 19, and the SECOND `debug_locals` —
    a fourth separate HTTP request — reads stage="after". The final `debug_continue` runs the program to
    completion, and its result carries both the `exit` event and the program's own stdout, complete
    because the session closes (and the process is reaped) inside that same call.
  * BLOCK 2 — THE HONEST REFUSALS, each of which could have been an empty result and is not. `locals`
    before any start says there is no session AND says which header carries one; a second `debug_start`
    on a live session is refused BY NAME rather than silently abandoning a running process; a breakpoint
    on a comment line is reported `no-code` rather than `set`; `debug_stop` on a live debuggee reports
    `terminated` rather than an exit code the program never chose; and `locals` afterwards distinguishes
    "the session you had has finished" from "there is no session", because those send an agent somewhere
    different.
  * BLOCK 3 — THE TRANSPORT REFUSALS. An unknown `Mcp-Session-Id` gets 404 and a reason, never a quietly
    minted fresh session (which would silently discard the caller's breakpoints). A foreign `Origin` gets
    403 before anything is parsed, dispatched, or compiled: this server builds and RUNS programs, so
    without that check a web page the user merely visits could drive it.
  * BLOCK 4 — THE BIND. This host's own non-loopback address cannot reach the server, which is the
    property that keeps the port off the network. It is a PROBE, not a claim: if this host has no
    non-loopback IPv4 at all the block fails loudly saying so, because a security gate that silently
    skips is worse than none.
  * BLOCK 5 — REMOVING a breakpoint, and leaving a loop. `debug_clear` takes exactly what debug_break
    takes and resolves it through the SAME path, so it removes what the identical `break` armed; asked
    a SECOND time it answers `not-set` rather than `cleared`, because telling an agent it removed
    something that was not there is how a mistyped target goes unnoticed. Then `debug_until` runs to a
    named line without stepping every statement in between. The program still exits 5: removing a
    breakpoint changes where it stops, never what it computes.

WHAT IS STABLE vs BUILD-SPECIFIC:
  * The event shapes, tool answers, refusal wordings, HTTP status codes, values and exit code are the P5
    subject and are STABLE. `Mcp-Session-Id` is fresh per run and is deliberately NEVER printed — it is
    captured into a shell variable and echoed back as a header, so nothing in these transcripts pins it.
  * The `.text` offsets (0xe4 for line 19, 0x121 for line 22, 0x51 the entry-stub return) are
    build-specific and move only if codegen for `main` moves.
  * The port is FIXED at 47821 rather than chosen: a server that silently moved to another port would
    leave a configured client talking to something else, so a taken port is a loud failure instead.
