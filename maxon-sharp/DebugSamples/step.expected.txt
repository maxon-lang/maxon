P4b source-line-stepping gate — reproducible transcript over DebugSamples/step.maxon.

HOW TO REPRODUCE (from a checkout that has built the C# compiler):
  maxon build maxon-sharp/DebugSamples/step.maxon
  maxon debug --batch --commands='break step.maxon:21; run; step; next; finish' maxon-sharp/DebugSamples/step.exe

RED (the same command against a pre-P4b binary, before this rung): step/next/finish were unknown words,
so each emitted `{"event":"error","message":"unknown command '<word>'"}` in place of a stop, e.g.
  {"event":"error","message":"unknown command \u0027step\u0027"}
  {"event":"error","message":"unknown command \u0027next\u0027"}
  {"event":"error","message":"unknown command \u0027finish\u0027"}

WHAT EACH COMMAND PROVES (asserted by the JSON below):
  * break step.maxon:21 / run  -> stop at main:21 (the `let a = helper(3)` call), reason "breakpoint".
  * step   -> DESCENDS INTO the call: reason "step", function "helper", line 15 (helper's first statement).
  * next   -> STEPS OVER the deeper(n) call: reason "step", function "helper", line 16 (the next statement
              in the same function; deeper() ran to completion via a temp bp, never single-stepped).
  * finish -> RETURNS to the caller: function "main", line 21 (the return point after helper(3)). Its
              reason is "breakpoint" because finish runs to a temp breakpoint at the return address — the
              location is what matters, and it is honestly the caller frame.

WHAT IS STABLE vs BUILD-SPECIFIC:
  * The event shapes, functions, lines, and reasons are the P4b subject and are STABLE.
  * The `.text` offsets (0x9f/0xab the main call+return, 0x1cb/0x1d3 helper's two statements, 0x4c the
    entry-stub return) are build-specific and move only if codegen for main/helper/deeper moves.
  * Exit code is 8 (helper(3) = deeper(3)+1 = 7; then the loop adds 0 and 1 -> 8). In --batch the target
    has no stdout of its own here, so the JSON channel on stdout is the whole transcript.
