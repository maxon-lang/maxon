# Large Frames Must Not Clobber Argument Registers

## Documentation

A frame larger than 4 KiB cannot be allocated by subtracting from `rsp` in one
step: Windows grows the stack one guard page at a time, and skipping a guard page
faults the process. The prologue therefore calls `__chkstk`, which touches each
4 KiB page on the way down.

`__chkstk` needs the frame size in a register, and the prologue runs BEFORE the
incoming argument registers are spilled to their stack slots. So the register it
uses must be one that carries no argument.

The internal calling convention is `rcx, rdx, r8, r9, rsi, rdi, rax, rbx` — **RAX
is parameter 7**. Passing the probe size in RAX therefore destroyed parameter 7 of
every function that had one and a frame over 4 KiB, before that parameter was ever
read. It is a silent wrong-answer miscompile, not a crash, and it is invisible to
any function with six parameters or a small frame. The size travels in R11 instead:
caller-saved, not an argument register, and dead at function entry — the discipline
`__gt_morestack` and the arm64 probe (X16/X17) already follow.

This test is the gate. `wide` takes seven parameters and keeps 700 locals live at
once, which forces the frame past 4 KiB and sends the prologue down the `__chkstk`
path. Its result depends on parameter 7, so a clobbered RAX changes the answer:
the pre-fix compiler returned 192 instead of 7.
