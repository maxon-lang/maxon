Maxon ships as a single compiler and the standard library it reads. There is nothing else to install
— no runtime, no toolchain, no SDK.

For a full walk-through — every platform, the VS Code extension, and verifying your install — see the
dedicated [Install page](/install/).

## Install

<Tabs syncKey="os">
  <TabItem label="Windows">

```bash
winget install MaxonLang.Maxon
```

Or download the `.msi` from the [latest release](https://github.com/maxon-lang/maxon/releases/latest)
and run it. It installs to `C:\Program Files\Maxon` and adds that directory to your PATH.

The installer is code-signed, so Windows runs it without a SmartScreen prompt.

  </TabItem>
  <TabItem label="macOS">

```bash
curl -fsSL https://maxon.dev/install.sh | sh
```

The script downloads the release for your Mac, checks it against the release's published checksums,
unpacks it into `~/.local/share/maxon` and links `~/.local/bin/maxon` to it, adding `~/.local/bin` to
your PATH in your shell profile if it is not there already. Open a new terminal, or run the `export`
line it prints, and `maxon` is ready. Run it again to upgrade. Nothing it downloads is quarantined, so
there is no Gatekeeper warning to click through. [Read the script](/install.sh) before you run it, if
you like.

Pass options after `sh -s --`: `--version 0.1.0` installs a particular release, and
`--no-modify-path` leaves your shell profile alone.

**With Homebrew**, `brew install maxon-lang/tap/maxon` works too. The tap prefix is required and cannot
be shortened: a bare `brew install maxon` resolves to Maxon Computer's Cinema 4D installer, which is a
different product that happens to share the name.

**By hand**, download the archive from the
[latest release](https://github.com/maxon-lang/maxon/releases/latest), extract it somewhere permanent,
and add that directory to your PATH. A browser download is quarantined by Gatekeeper whatever is
inside it, so clear that once:

```bash
tar -xzf maxon-*-arm64-macos.tar.gz
cd maxon-*-arm64-macos
xattr -d com.apple.quarantine ./maxon
export PATH="$PWD:$PATH"
```

  </TabItem>
  <TabItem label="Linux">

```bash
curl -fsSL https://maxon.dev/install.sh | sh
```

The same script as on macOS: it picks the x64 or arm64 build, checks it against the release's
published checksums, unpacks it into `~/.local/share/maxon` and links `~/.local/bin/maxon` to it. The
builds are static and need no libc, so any reasonably current distribution will do.

**By hand**, download the archive from the
[latest release](https://github.com/maxon-lang/maxon/releases/latest), extract it somewhere
permanent, and add that directory to your PATH:

```bash
tar -xzf maxon-*-x64-linux.tar.gz
cd maxon-*-x64-linux
export PATH="$PWD:$PATH"
```

  </TabItem>
</Tabs>

:::caution[Keep the compiler and the standard library together]
The compiler finds `stdlib/` by walking **up from its own executable**, so moving `maxon` somewhere
else on its own leaves it with no standard library. Move the whole directory, or put it on your PATH
as it is.
:::

## Verify

```bash
maxon version
```

Then write and run [your first program](/docs/getting-started/first-program/).

## Building from source

Maxon is written in Maxon, so building it needs a Maxon compiler — there is no second implementation
to fall back on.

**Prerequisites:** Git, and Node.js 20+ only if you are building the VS Code extension.

Install a release first, as above, then:

```bash
git clone https://github.com/maxon-lang/maxon.git
cd maxon

mkdir -p .bootstrap && cp "$(command -v maxon)" .bootstrap/   # the seed
scripts/build-from-seed.sh                                     # build the compiler with it, twice
maxon-bin/.maxon/maxon spec-test                               # run the suite
```

The seed builds the compiler, and that compiler then rebuilds itself: the compiler emits its runtime
into everything it builds, itself included, so only the second build carries this tree's runtime.
Afterwards, `maxon-bin/.maxon/maxon build maxon-bin` rebuilds it through the repository's own
[build manifest](/docs/language/build-system/).

Build this tree with the compiler inside it, never the `maxon` on your PATH: that one would compile the
repository against its own release's standard library, and succeed.

:::caution[Seed with the binary alone]
Copy the `maxon` **binary** into `.bootstrap/`, not the unpacked archive. The compiler resolves
`stdlib/` by walking up from its own executable, so a released `stdlib/` left beside the seed would be
compiled in place of the checkout's own — the build would succeed, and compile the wrong library.
:::
